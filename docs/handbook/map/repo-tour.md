# Repo tour

Every top-level folder and config file in the repository: what it is and when you will touch it. Layout rules live in [CODING_STANDARDS section 2](../../CODING_STANDARDS.md) and [SRS section 3.2](../../SRS.md).

How often you touch it: **daily** (normal feature work), **sometimes**, **rarely** (setup, tooling), **never by hand** (generated or managed by a tool).

## Folders

| Path                                 | What it is                                                                                                                                                                            | Touch it                                |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| `apps/web`                           | The Next.js website and the place the API is mounted (`src/app/api/[[...route]]/route.ts`). Has its own `CLAUDE.md` and `Dockerfile`.                                                 | daily                                   |
| `packages/api`                       | The Hono API: `routes/`, `middleware/`, `domain/`, `ports/`, `adapters/`, `container.ts`, `app.ts`. See [hexagonal](../patterns/hexagonal-ports-adapters.md).                         | daily                                   |
| `packages/engine`                    | The pure pattern engine (`geometry/`, `sleeve/`, `errors/`, `version.ts`). See [functional core](../patterns/functional-core-plugin-pipeline.md).                                     | daily (engine issues)                   |
| `packages/schemas`                   | Zod contracts shared by web, API and engine. See [schema-first](../patterns/schema-first-contracts.md).                                                                               | when a data shape changes               |
| `packages/ui`                        | Shared, RTL-first components such as `Button`.                                                                                                                                        | when UI repeats twice                   |
| `packages/config`                    | `env.ts`: the one place environment variables are read and validated.                                                                                                                 | when adding a setting                   |
| `packages/utils`                     | Small generic helpers (`units.ts`).                                                                                                                                                   | sometimes                               |
| `packages/test-fixtures`             | Shared test data: sizes, measurement sets, designs.                                                                                                                                   | when tests need new data                |
| `services/sim`                       | Python simulation service (v2). Only a template `Dockerfile` exists today.                                                                                                            | rarely (v2)                             |
| `supabase/`                          | `migrations/` (empty until M1) and `seed.sql` (placeholder). The database lives here as code.                                                                                         | when the database changes (M1+)         |
| `postman/`                           | Postman collection, environments and test scripts for the API; the collection is generated by `scripts/gen-postman.mjs`.                                                              | via `pnpm api:postman` (planned script) |
| `docs/`                              | All documentation: SRS, ARCHITECTURE, DECISIONS, WORKFLOW, CODING_STANDARDS, `backend/`, `engine/`, `frontend/`, `plans/`, `test-cases/`, `handbook/`.                                | every PR                                |
| `scripts/`                           | Helper shell and Node scripts: `bootstrap.sh`, `gh-ac.sh` (tick acceptance criteria), `gh-project.sh` (move board cards), `setup-labels.sh`, `test-case-index.sh`, `gen-postman.mjs`. | rarely                                  |
| `.claude/`                           | Agent setup: `commands/` (slash commands such as `/build`), `rules/` (path-scoped rules), `skills/` (task recipes).                                                                   | when the process changes                |
| `.github/`                           | `workflows/` (CI), issue and PR templates, `labels.yml`, `ci.env` (placeholder values for CI).                                                                                        | rarely                                  |
| `.husky/`                            | Git hooks. `pre-commit` runs `lint-staged` on staged files.                                                                                                                           | rarely                                  |
| `reports/`                           | Output of the duplicate-code check (`jscpd`). Ignored by Prettier.                                                                                                                    | never by hand                           |
| `node_modules/`, `.turbo/`, `.next/` | Installed packages and caches, created by tools.                                                                                                                                      | never by hand                           |

## Root files

| File                                   | What it does                                                                                                                       | Touch it                         |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `package.json`                         | Root scripts (`pnpm dev`, `test`, `quality`...), pinned `packageManager`, dev tools. Declares required Node (`>=22.22.2 <23`).     | when adding a script or dev tool |
| `pnpm-workspace.yaml`                  | Says which folders are packages: `apps/*` and `packages/*`. See [workspace](../glossary.md#workspace).                             | rarely                           |
| `pnpm-lock.yaml`                       | Exact versions of every dependency. See [lockfile](../glossary.md#lockfile).                                                       | never by hand                    |
| `turbo.json`                           | [Turborepo](https://turborepo.com/docs) tasks (`build`, `dev`, `test`, `typecheck`) and their caching.                             | rarely                           |
| `tsconfig.base.json`, `tsconfig.json`  | Shared strict TypeScript settings; each package extends the base.                                                                  | rarely                           |
| `eslint.config.mjs`                    | Lint rules: complexity limits, JSDoc on every function, no `any`. See [code style](../code-style.md).                              | rarely                           |
| `.prettierrc.json`, `.prettierignore`  | Formatting rules (110 columns, double quotes) and ignored paths.                                                                   | rarely                           |
| `.editorconfig`                        | Editor basics: UTF-8, LF line endings, 2 spaces.                                                                                   | rarely                           |
| `.jscpd.json`                          | Duplicate-code detector settings (50 tokens, 5 lines).                                                                             | rarely                           |
| `.dependency-cruiser.cjs`              | Architecture rules: who may import whom. See [hexagonal](../patterns/hexagonal-ports-adapters.md).                                 | when a layer rule changes        |
| `.nvmrc`, `.python-version`            | Pinned Node major (22) and Python version for [nvm](https://github.com/nvm-sh/nvm) and `uv`.                                       | when upgrading                   |
| `.npmrc`                               | pnpm settings: `engine-strict=true` makes a wrong Node version a hard error.                                                       | rarely                           |
| `.env.example`, `.env.docker.example`  | Documented list of environment variables. Copy to `.env.local` or `.env.docker`; never commit real secrets.                        | when adding a variable           |
| `.env.local`                           | Your private local values (ignored by git).                                                                                        | yourself, never commit           |
| `compose.yaml`                         | [Docker Compose](https://docs.docker.com/compose/) services: Inngest dev server, the production web image, sim, Newman.            | sometimes                        |
| `.dockerignore`, `apps/web/Dockerfile` | What goes into the container image and how it is built (multi-stage, non-root).                                                    | rarely                           |
| `CLAUDE.md`, `AGENTS.md`               | Instructions for AI agents. `CLAUDE.md` is the project rulebook and status; `AGENTS.md` carries tool-managed guidance (Turborepo). | `CLAUDE.md` every session        |
| `README.md`                            | Short "how to start" for humans.                                                                                                   | rarely                           |

## Where does my change go?

Use the table in [CODING_STANDARDS section 2](../../CODING_STANDARDS.md): geometry in `packages/engine`, data shapes in `packages/schemas`, business logic in `packages/api/src/services/`, database and vendor code in `packages/api/src/adapters/`, reusable UI in `packages/ui`, one screen's parts in `apps/web/src/features/<feature>/`.
