# Error catalogue

Every error the API returns has a code defined in `ERROR_CATALOGUE` (`packages/api/src/domain/errors.ts`). The body is always `{ code, message_ar, message_en, details?, request_id }` (ADR-030). A test (`errors.test.ts`) fails when a thrown code is missing from the catalogue or from this table, or when its Arabic message is missing.

How the web app shows each case: [docs/frontend/README.md](frontend/README.md#error-display).

## Browser-only codes (export worker, issue #289)

These never come from the API. The export worker posts them and `exportErrorToApiError` (`apps/web/src/shared/pattern-export/export-error.ts`) turns them into the shared error display; the texts live in `messages/` under `patternExport.errors`.

| Code               | Shown as                                         | Cause                                                                      | What to do                                  |
| ------------------ | ------------------------------------------------ | -------------------------------------------------------------------------- | ------------------------------------------- |
| `FONT_LOAD_FAILED` | "The font could not be loaded..." with Try again | `/fonts/IBMPlexSansArabic-*.ttf` could not be fetched (offline, blocked)   | Check the connection and try again          |
| `PDF_BUILD_FAILED` | "The file could not be built. Try again."        | `pdf-lib` or the tile code threw                                           | Try again; if it repeats, report the design |
| `WORKER_FAILED`    | Same as above                                    | The export worker crashed or could not load                                | Try again                                   |
| `PATTERN_INVALID`  | "This design ... cannot be exported."            | The stored inputs no longer pass validation (saved versions never do this) | Open the version and read the report        |

## Browser-only codes (fabric nesting worker, issue #318)

The nesting worker posts these and `fabricErrorToApiError` (`apps/web/src/shared/fabric-nesting/fabric-error.ts`) turns them into the shared error display; the texts live in `messages/` under `fabric.calc.errors`. Engine input errors keep their own text.

| Code              | Shown as                                           | Cause                                        | What to do                           |
| ----------------- | -------------------------------------------------- | -------------------------------------------- | ------------------------------------ |
| `PATTERN_INVALID` | "This pattern did not pass validation..."          | The stored inputs no longer pass validation  | Open the version and read the report |
| `WORKER_FAILED`   | "The calculation stopped unexpectedly. Try again." | The nesting worker crashed or could not load | Try again                            |

## Adding a code

1. Add it to `ERROR_CATALOGUE` with both messages (Arabic first).
2. Add a row above.
3. Throw it with `new AppError("CODE", { details })` from a use case; never build an error body by hand.
