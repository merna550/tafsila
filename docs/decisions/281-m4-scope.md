# ADR-281 · 2026-10-25 · M4 scope: outputs from a saved version, built in the browser

**Context:** M4 (Outputs) adds the projector with calibration, direct-cut steps and the A4/A0 PDF (SRS §12). The brief is `docs/milestones/M4-outputs.md`, issues #281-#296. Several points were not written down: which pattern an output uses, where the PDF is made, whether exports are stored, where calibration lives, the direct-cut reference lines, routes, and what the exit waits for. All are cheap to change before the beta (no production data, ADR-026).
**Decision:**

1. **Outputs open from a saved version only.** Projector, direct cut and export start from the read-only version view (`/designs/[id]/versions/[versionId]`, ADR-252). The version number and engine version are printed on every output, so a print can always be traced back. An unsaved pattern shows the buttons disabled with a reason.
2. **Everything runs in the browser.** The worker regenerates the pattern and scene from the version's stored inputs (ADR-236 item 2, ADR-252 item 2). M4 adds no API route, no table and no server job.
3. **The PDF is built in a browser Web Worker** with `pdf-lib` (confirmed or replaced by the spike #282). The `exports` table, `POST /api/versions/:id/exports`, the Inngest `export.pdf` job and 30-day file storage (FR-EXP-05) are **deferred** until a measured need: the A4 build misses NFR-02 (< 20 s) on a mid laptop, or billing (M7) needs a server record of exports. Reason: Vercel Hobby function limits and Supabase Free storage (ADR-022), and the engine is deterministic, so a file can always be rebuilt.
4. **New package `packages/export`** (SRS §3.2) holds the tile maths and the PDF builders. The engine stays dependency-free; only `packages/export` depends on `pdf-lib`.
5. **Direct-cut steps mark the cut line** (seam allowance included), relative to the fold line when the piece has a `fold` edge, otherwise a line parallel to the grain through the leftmost cut point (the selvedge side), plus the perpendicular through the top of the piece. Curves are offset points every 25 mm by default (20-30 allowed, FR-CUT-02). The engine makes the steps (`cutSteps`); the UI only shows them.
6. **Routes:** `/designs/[id]/versions/[versionId]/projector`, `.../projector/calibrate` and `.../cut`. Export is a dialog on the version view.
7. **Calibration is per device** in `localStorage` (`tafsila.projector.calibration`: `pxPerMmX`, `pxPerMmY`, screen size, pixel ratio, date), as FR-PROJ-02 says. It is ignored when the screen size or pixel ratio changes, or when storage fails, and the projector asks to calibrate again. Projector piece placements and direct-cut ticks are per viewer and per version in `localStorage` too; nothing is saved to the server.
8. **Out of M4:** keystone (FR-PROJ-06, C), DXF (FR-EXP-04, C), projecting a fabric layout (FR-FAB-04, M5), credits (M7).
9. **Physical checks are Merna's issues** (#184): projector accuracy and toile #294, PDF prints and toile #295, direct-cut toile #296. The M4 exit #293 waits for #294 and #295; the direct-cut toile is not in the exit criterion.
10. **M4 does not wait for the M3 exit (#254) or the M2 exit (#148).** The M4 toiles use a dress or skirt that engine bugs #229-#232 do not touch.
11. **Screens first.** UI issues match designs copied to `docs/design/screens/` by #281 (ADR-97).

**Reason:** Outputs from saved versions are traceable and need no new storage. Building in the browser keeps M4 on the free tiers and reuses the worker M3 already has. A separate package keeps `pdf-lib` out of the engine and out of page bundles.
**Alternatives:** Server-side PDF through an Inngest job with stored files (more moving parts, storage limits on Supabase Free, slower feedback; kept for later); outputs from the unsaved pattern page (prints that match no version); calibration in the user profile (a factor belongs to one projector and screen, not to a person); direct-cut steps on the stitch line (the tailor then adds seam allowance by hand, a common source of error).
