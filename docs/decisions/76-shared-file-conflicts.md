# ADR-76 · 2026-10-11 · Shared files that every PR touches: untracked index, one file per decision, no per-PR status log

**Context:** Parallel PRs conflicted on the same files after each merge (#52, #75, #77, issue #76): the generated `docs/test-cases/index.md` (every PR regenerated it), `docs/DECISIONS.md` (everyone inserts at the top, and two PRs took the same number: ADR-020 and ADR-032), the "Last done" line in `CLAUDE.md` (one long line every PR rewrote) and, less often, `docs/handbook/learning-log.md` (rows added at the top).
**Decision:** (1) `docs/test-cases/index.md` is generated and not committed (`.gitignore`); `/release-check` runs `scripts/test-case-index.sh` first. (2) `docs/DECISIONS.md` is closed at ADR-035. New decisions are one file each in `docs/decisions/<issue>-<slug>.md`, numbered by the issue that decides them. (3) `CLAUDE.md` no longer keeps a "Last done" log; its status holds the milestone, the next step and the open decisions, updated only when they change. (4) `pnpm docs:check` fails on a duplicated ADR number, on a decision file whose name and heading disagree, and on a file without an issue number.
**Alternatives:** `merge=union` in `.gitattributes` (GitHub's merge ignores it, so PRs would still show as conflicted); a merge queue (not on the free plan for private repos); rebasing open PRs automatically (rewrites other people's branches); numbering ADRs by "next free number" (the cause).
**Still conflict-prone:** `docs/handbook/learning-log.md` (one row per PR at the top). It is a small table and the conflict is trivial (keep both rows); it can move to one file per row if it keeps hurting.
