# ADR-25a · 2026-10-11 · Auth (#25, #90, #91): locale URLs and the locale layout

**Context:** Issue #25 (sign-up, sign-in) was split into #90 (i18n foundation and web e2e), #91 (session and API auth) and #25 (screens). The ADR-025 file prefix in the closed log is taken, so this file uses `25a`. This part writes only decision 2 and the layout detail below; B and C append their decisions here.
**Decision:** (1) The split into #90, #91 and #25 is approved by Merna. (2) URLs: Arabic is the default and has no prefix (`/sign-in`), English lives under `/en` (`/en/sign-in`), `localePrefix: "as-needed"`. The ADR-72 redirect `/sign-in?next=` keeps working. The locale is remembered in the next-intl cookie; #27 later stores it in `profiles.locale`. (3) `app/[locale]/layout.tsx` renders `<html lang dir>` itself and also holds the font and the observability provider; there is no root `app/layout.tsx`, because Next requires the `<html>` element in the root layout and `lang`/`dir` depend on the URL locale. (4) The error-display texts moved from `shared/error-display/messages.ts` (deleted) to `messages/{ar,en}.json` under `errors` (ADR-72 (4)); the home-page exemption from the literal-text rule is removed (ADR-029 (6)). (5) `request.ts` still uses `requestLocale`, which next-intl marks deprecated in favour of the experimental `next/root-params`; the proxy sets it on every request, so the stable API is used until root params leave experimental.
**Reason:** Arabic is the main audience, so its URLs stay clean; one routing definition feeds the proxy, the request config and the navigation helpers.
**Alternatives:** Always-prefixed URLs (`/ar/...`; breaks the `/sign-in?next=` links already in use); a root layout with `<html>` and a `getLocale()` call (works, but splits `lang`/`dir` from the locale segment that owns them).
