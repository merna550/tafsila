# ADR-122 · 2026-10-13 · M2 engine scope: full catalogue, own geometry, 1:1 SVG toiles, one drafting system

**Context:** M2 (Engine core) has to deliver validated patterns for dress, skirt and blouse and toiles in 3 sizes per garment (SRS §12) before any PDF export exists (M4). SRS §13 item 2 left FreeSewing (licence, fork vs dependency) open, and no drafting system for the blocks was chosen.
**Decision:** (1) M2 covers the full v1 catalogue of SRS §6.1, split into 28 issues in 5 waves (brief `docs/milestones/M2-engine-core.md`), so the M3 picker has every option. (2) No runtime dependency on FreeSewing: the engine keeps its own pure geometry kit (`src/geometry/`); FreeSewing (MIT licence) is only a cited reference for curve construction, with attribution in JSDoc where a method is borrowed. This closes SRS §13 item 2. (3) Toiles in M2 are printed from a deterministic 1:1 SVG (`pnpm engine:print`) at a plotter print shop, with a 10 cm scale square; A4/A0 PDF stays in M4. (4) The 20 custom measurement sets in the size matrix are synthetic until Merna supplies anonymised real sets (data only). (5) All blocks follow one documented drafting system with hand-computed reference drafts; the system itself is Merna's choice in #122 (proposal: Aldrich, metric), because it sets the fit of every garment.
**Reason:** One dependency-free engine that runs the same in the browser and on the server (ADR-002, NFR-08); toiles can be sewn without waiting for M4; fit-defining choices stay with the sewing expert.
**Alternatives:** Depend on or fork `@freesewing/core` (its plugin model and units differ from our `PatternResult`; a fork would be maintained alone); a core subset of the catalogue in M2 and the rest later (M3 picker would show half the options); wait for PDF export to sew toiles (fit errors found two milestones late).
