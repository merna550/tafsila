# ADR-83 · 2026-10-11 · Finish cutting Actions minutes: database proof, caches, 12-hour dispatcher cron

**Context:** The free Actions minutes ran out again on 2026-10-11 (PRs #81 and #82). [ADR-86](86-cut-actions-minutes.md) already added path scoping for Storybook, Docker, e2e and the API checks and cancelled superseded runs of `quality.yml` and `docker.yml`. Numbers from `node scripts/actions-usage.mjs` (last 30 days, 531 runs, about 1876 minutes): Docker image 1485, Dispatch agent 226 (223 runs, mostly the 6-hour cron and events with nothing to build), Code quality 84, Staging 33, Claude agent 14, other 35. The Billing page figures that Merna was asked to paste (issue #83) were not available when this was built; add them here when pasted. They only decide the order of further work, not this change.
**Decision:** (1) `supabase.yml` (`db-reset`, which starts the whole local Supabase) uses the same pattern as ADR-86: a `scope-db` job runs `scripts/ci-paths.mjs supabase` (`supabase/**`, root toolchain files, the workflow; never Markdown) and `db-reset` is skipped by its `if`, so it can be required without blocking merges. It replaces `on.paths`. (2) `supabase.yml` and `docs-links.yml` cancel superseded PR runs (never `main`, the weekly lychee run or the dispatcher, whose group keeps `cancel-in-progress: false`). (3) The Playwright browsers (`~/.cache/ms-playwright`) are cached by `pnpm-lock.yaml` hash in the Storybook and e2e jobs; the pnpm store is already cached by `actions/setup-node`. (4) The dispatcher cron goes from every 6 to every 12 hours; events (label, close) stay, so work still starts at once, and the cron only catches missed events. `DISPATCH_DAILY_LIMIT` stays 4. (5) [docs/backend/ci-minutes.md](../backend/ci-minutes.md) explains how to read the Usage page, what costs minutes and a rule of thumb (batch pushes per PR).
**Reason:** `db-reset` ran on every PR that touched `package.json` and on pushes with `supabase/**` only; the scope job also covers lockfile and toolchain changes correctly. A 12-hour cron halves the idle dispatcher runs without delaying event-driven work.
**Alternatives:** `lychee` stays on `on.paths: docs/**` (it is not a required check and its action only reads `docs/**/*.md`, so a skipped-job pattern would add a scope job for no benefit); dropping the cron completely (a missed event, such as a label change made with `GITHUB_TOKEN`, would then wait for a human); a daily cron (kept as the next step if usage stays high); dropping arm64 emulation on `main` (the biggest saving, still open for Merna, see ADR-86).
