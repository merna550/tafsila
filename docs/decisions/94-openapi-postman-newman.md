# ADR-94 · 2026-10-11 · OpenAPI from the routes, a stable Postman collection and Newman without Docker

**Context:** The Definition of Done asks for `pnpm api:openapi && pnpm api:postman` and `pnpm api:test`, but none of the scripts existed, so `/api/me` and `/api/health` were documented only in the SRS (issue #94). GitHub Actions minutes are limited (ADR-86) and the free tiers rule out paid tools (ADR-022).
**Decision:**

1. **`@hono/zod-openapi`** (MIT, official Hono package, native Zod 4) declares the routes (`createRoute` + `.openapi`), so the Zod schemas are the single source for validation and the document. Examples use Zod 4 `.meta({ example })`; this reaches the document. Errors are documented with `errorResponses(...)` using `apiErrorBodySchema` and the catalogue messages. A `defaultHook` turns any request validation failure into the standard `VALIDATION_FAILED` body.
2. **The document is committed at `packages/api/openapi.json`**, built from `createApp` with a fixed container so the output is byte-stable; written with `tsx` (new dev dependency). `/api/openapi.json` is served in every environment; the Scalar viewer at `/api/docs` (version-pinned jsDelivr script) is served outside production only. The web app sets no CSP, so the CDN is not blocked.
3. **`pnpm api:postman`** converts the document with `openapi-to-postmanv2`, removes random ids, drops example responses, sorts items, leaves the `debug` route out and appends the `ERR` cases from `postman/err-cases.json`. Running it twice changes nothing.
4. **`pnpm api:test`** runs Newman against a throwaway local API (`packages/api/src/dev/test-server.ts`: real routes, a local test key pair, a signed `user` token, random port). No Docker, no Supabase. `--base-url` runs the same collection against any API with the real login. `--break=health` proves a broken route fails the run.
5. **`pnpm api:check`** (inside `pnpm quality`) fails when the committed document or collection is stale. In CI, `scripts/ci-paths.mjs api` gates two `if` steps (`api:check`, `api:test`) inside the existing quality job, so no new job and no required check can disappear.
   **Reason:** One source of truth that cannot drift, the checks cost seconds and run only when the API or Postman files change, and nothing needs Docker or a paid plan.
   **Alternatives:** `hono-openapi` (third party, more adapters than needed); a hand-written generator (duplicates the library, drifts); a separate CI job (Actions minutes, a required check could go missing); Newman against Supabase in CI (needs Docker, out of scope).
   **Cannot run locally or in CI here:** real Supabase login, admin role, real JWKS and anything database backed; M1 endpoint issues add their own cases. The new workflow steps cannot run until Actions minutes return; every command was run locally.
