# ADR-337 · 2026-11-01 · AI package: patch rules in the engine, fake provider, drift-tested catalogue, one retry

**Context:** Issue #337 builds `packages/ai` (`@tafsila/ai`), the provider-neutral package [ADR-335](335-m6-scope.md) item 1 asks for: `analyzeDesign` and `proposeEdit` on the Vercel AI SDK, with the AI only filling or editing a `DesignSpec` ([ADR-002](../DECISIONS.md)). Five points were not written down. None is costly to reverse.

**Decision:**

1. **`applySpecPatch` lives with the engine spec rules** (`packages/engine/src/spec-rules/apply-spec-patch.ts`, exported from `@tafsila/engine/spec-rules`). It applies the ops of a `SpecPatch` in order, then the schema and `specRefusals`; it rejects the whole patch on an unknown path or value, a feature the category has no part for, a length outside `OVERRIDE_LIMITS_MM`, or a combination the engine refuses. One place validates specs; the picker, the AI and later the API share it. The feature path list moved to `@tafsila/schemas` (`DESIGN_FEATURE_PATHS`); the engine re-exports it as `FEATURE_PATHS`, so there is still one list.
2. **`fake` is a first-class provider** and the default everywhere except production, where it is refused. It is a real AI SDK language model that answers from `packages/ai/src/fixtures/answers.ts` (analysis by category hint, chat by keyword in Arabic or English), so the real call path (schema, tools, retry) runs in tests, local dev and CI without a key. The fixtures are built from the engine's starting designs, not copied.
3. **The prompt catalogue is English text keyed by enum value** (`FEATURE_DEFINITIONS`); the values come from `designSpecSchema` through the engine's `candidateValues`. `buildCataloguePrompt` throws and a test fails when a schema value has no definition or a definition has no value. The model needs no Arabic definitions; its notes to the user are bilingual.
4. **Retry once with the validation error, then a typed result.** Analysis: the model's invalid answer and the error go back once; a second failure throws `AiOutputInvalidError` (`AI_OUTPUT_INVALID`). Chat: invalid tool calls or a patch `applySpecPatch` refuses go back once with the reasons; a second failure returns an empty patch marked unsupported (the chat can always answer). An analysed spec the engine refuses is passed through `normalizeSpec`; each changed feature gets confidence 0 and a note.
5. **Cost is an estimate** from one price table (`PRICE_TABLE_USD_PER_MTOK`, US dollars per million tokens) and `ai_usage` stores it as such. Only `fake` (free) has a row now; a real model gets its row when the provider evaluation (#347) picks it, and until then its cost is `undefined` rather than guessed.

Also: the chat model variable is `AI_MODEL_CHAT`, next to the existing `AI_MODEL_ANALYZE` (ADR-021). ADR-335 and the issue wrote `AI_ANALYZE_MODEL`/`AI_CHAT_MODEL`; renaming the existing variable would break staging settings for no gain. A dependency-cruiser rule keeps `@tafsila/ai` server-only: only `packages/api` imports it, and it never imports the API, web or UI. AI SDK packages are pinned to exact versions (`ai` 7.0.142, `@ai-sdk/anthropic` 4.0.81, `@ai-sdk/google` 4.0.98) because the SDK changes fast; the provider wrappers are all in `packages/ai/src/provider.ts`.

**Alternatives:** `applySpecPatch` in `@tafsila/schemas` (cannot run the engine's refusals; schemas is a leaf package). A mock only in tests (local dev and e2e would need a key or a second code path). A hand-written catalogue (drifts silently when an enum gains a value). Throwing on a refused chat patch (the chat would show an error for a request it can simply decline). Guessing prices for models not chosen yet.
