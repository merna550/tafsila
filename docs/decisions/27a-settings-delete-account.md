# ADR-27a · 2026-10-13 · Profile endpoints and account deletion (Part A)

**Context:** Issue #27 (FR-AUTH-04 delete account, FR-AUTH-05 language, NFR-05, Egypt Law 151/2020). Part A (database function, API, config) is built; Part B (the `/settings` screen) follows. Plan: `docs/plans/27-settings-delete-account.md`.
**Decision:**

1. **Deletion order: files, analytics, auth user, audit; an audit failure never fails the request.** The irreversible step (GoTrue admin delete) comes after the steps that can fail, and every step is safe to repeat, so a failure leaves the account intact and the person retries. Deleting the auth user first would orphan personal files nobody can find; one database transaction is impossible because GoTrue, Storage and PostHog are outside the database. **Security-sensitive.**
2. **Confirmation: a fixed literal in the body** (`{ "confirm": "DELETE_MY_ACCOUNT" }`, anything else is `VALIDATION_FAILED`), language independent. The screen (Part B) also asks for a typed word. No extra "sign in again" step: the token already proves the session; a "recent sign-in" check is cheap to add later.
3. **Admins cannot delete themselves through the app** (`ACCOUNT_DELETE_FORBIDDEN`, 403), so the project never loses its last admin by a click. The SQL path is in `docs/backend/tutorials/delete-account.md`.
4. **The account id always comes from the token.** Bodies are `.strict()`: a `userId` in the body is refused.
5. **Audit row has no identity.** `private.record_account_deleted()` (`security definer`, `execute` only for `api_app` and `service_role`) inserts `admin_audit (who null, action 'account.deleted')`. It is needed because `admin_audit` only lets admins insert and the user is already gone. Written last, after the user is deleted.
6. **PostHog erasure needs a private key.** `POSTHOG_PERSONAL_API_KEY` and `POSTHOG_PROJECT_ID` are optional, both or neither (`env.ts` refuses one alone). Without them a no-op eraser logs one warning and deletion continues, so local, CI and staging work. Production must have them before the beta (M8 checklist). The person is found by distinct id (the opaque user id; events never carry PII) and deleted with `delete_events=true`. A server `account_deleted` event is **not** sent: capturing after erasure would recreate the person. The event stays defined for the browser.
7. **Storage registry.** `domain/storage-buckets.ts` lists the buckets; a test fails when `supabase/config.toml` declares a bucket that is not in it. Removal walks `<userId>/` including sub-folders, pages of 100, and refuses an id that is not a UUID (an empty prefix would list everyone's files).
8. **Service role key.** Only `gotrue-account-deleter` and `storage-files-remover` (both in `adapters/supabase/`) hold it; the container wires them, no route or service sees it. Provider error bodies are never put in error messages (they can contain emails); only the HTTP status is.
9. **A deleted user's token stays valid until it expires (up to one hour).** Every route reads through RLS, which finds no profile: `GET /api/profile` answers 404, writes fail on foreign keys; `GET /api/me` still answers from the token. Acceptable for M1.
10. **The trial rule is kept by the database:** `trial_phones.user_id` is `on delete set null`, so the hash stays and the same number never gets a second trial (decision 26a, 3).
11. **Backups:** deleted rows may stay in Supabase backups until they expire. The privacy policy text (M8) must say so.
12. **Profile:** `GET`/`PATCH /api/profile` return `{ name, locale, email }`; email comes from the verified token claims. `PATCH` goes through `withUser`; the column grants of ADR-24a allow `authenticated` to update only `name` and `locale`. A `locale_changed` event (value only) is recorded.
13. **Postman:** `account` is never run by Newman (it deletes the signed-in account); the `profile` folder is replaced by journey steps 14 and 15.

**Tested here:** services, routes, adapters with a fake `fetch`, config, schemas, the OpenAPI document and the Newman run on memory adapters. **Not run in this environment (no Docker):** the pgTAP file `supabase/tests/database/account-deletion.test.sql` and the real-adapter end-to-end check against local Supabase; CI runs the pgTAP file.
