# Context map

Which files to read for each kind of task, **and only those** (issue #17, ADR-017). Read [CLAUDE.md](../CLAUDE.md) first, then the issue and its plan comment, then the row that matches. Read SRS sections by requirement ID, not the whole file. For anything else, ask the `code-search` subagent where it lives instead of opening many files.

- **Engine bug (wrong geometry, crash)**: [packages/engine/CLAUDE.md](../packages/engine/CLAUDE.md), [.claude/rules/engine/drafting.md](../.claude/rules/engine/drafting.md), the module under `packages/engine/src/<module>/` and its tests, [engine README](engine/README.md) section on units/validation. Use: Write the failing test first
- **Engine feature (new garment part)**: The engine-bug files plus [functional core pattern](handbook/patterns/functional-core-plugin-pipeline.md), the DesignSpec schema in `packages/schemas/src/`. Use: [add-garment-module](../.claude/skills/add-garment-module/SKILL.md)
- **New API endpoint**: [packages/api/CLAUDE.md](../packages/api/CLAUDE.md), [.claude/rules/backend/api-design.md](../.claude/rules/backend/api-design.md), [.claude/rules/backend/layering.md](../.claude/rules/backend/layering.md), [.claude/rules/backend/errors.md](../.claude/rules/backend/errors.md), [error catalogue](errors.md), [hexagonal pattern](handbook/patterns/hexagonal-ports-adapters.md), one existing route + service + test in `packages/api/src/` as the example, [add-endpoint tutorial](backend/tutorials/add-endpoint.md), [decision 94](decisions/94-openapi-postman-newman.md) (OpenAPI, Postman, Newman), `withApiRole` in `adapters/supabase/with-user.ts` for privileged `private.*` writes ([ADR-26a](decisions/26a-phone-otp-trial.md)), `packages/api/src/openapi/`. Use: [add-endpoint](../.claude/skills/add-endpoint/SKILL.md)
- **New screen / UI feature**: [apps/web/CLAUDE.md](../apps/web/CLAUDE.md), [.claude/rules/frontend/layering.md](../.claude/rules/frontend/layering.md), [.claude/rules/frontend/components.md](../.claude/rules/frontend/components.md), [.claude/rules/frontend/state-and-forms.md](../.claude/rules/frontend/state-and-forms.md), [.claude/rules/frontend/error-display.md](../.claude/rules/frontend/error-display.md), [.claude/rules/frontend/rtl-i18n.md](../.claude/rules/frontend/rtl-i18n.md), [docs/design/](design/README.md) (screen designs and copy rules), [frontend README](frontend/README.md) (i18n section: `shared/i18n`, `messages/`), [feature-sliced pattern](handbook/patterns/feature-sliced-frontend.md). Use: [add-page](../.claude/skills/add-page/SKILL.md)
- **Database migration**: [.claude/rules/backend/database.md](../.claude/rules/backend/database.md), the latest file in `supabase/migrations/`, [add-migration tutorial](backend/tutorials/add-migration.md), [seed data](backend/seed-data.md) and `supabase/seed.sql`. Use: Update seed data in the same PR
- **CI / Docker / environments**: The workflow in `.github/workflows/` named by the issue, [apps/web/Dockerfile](../apps/web/Dockerfile), [Docker tutorial](backend/tutorials/docker.md), [switch-environment tutorial](backend/tutorials/switch-environment.md), `packages/config/env.ts` for config. Use: Never deploy to production
- **Agent tooling (hooks, dispatcher)**: [.claude/settings.json](../.claude/settings.json), `scripts/hooks/`, [scripts/dispatch.mjs](../scripts/dispatch.mjs), [scripts/agent-model.mjs](../scripts/agent-model.mjs), `.claude/agents/`, `.claude/procedures/`, [run-agents-in-cloud tutorial](backend/tutorials/run-agents-in-cloud.md), [Claude Code card](handbook/tech/claude-code.md), [agent-usage tutorial](backend/tutorials/agent-usage.md), `scripts/agent-usage.mjs`, `scripts/agent-report.mjs`, WORKFLOW [section 2](WORKFLOW.md#2-choosing-the-model-save-tokens). Use: Add tests in `scripts/*.test.mjs`
- **Docs only**: The doc named by the issue, [handbook README](handbook/README.md) (rules for glossary and cards), [learning log](handbook/learning-log.md). Use: `pnpm docs:check`
- **Test cases only**: [test-cases README](test-cases/README.md), [template](test-cases/_TEMPLATE.md), the existing file for the feature. Use: `scripts/test-case-index.sh`

For a new endpoint, web feature or garment module, run `pnpm gen endpoint|feature|garment-module <name> <issue>` first; it writes the boilerplate and its tests, and you write only the logic (decision 33a).

Every task also needs the Definition of Done in [WORKFLOW section 5](WORKFLOW.md#5-definition-of-done-before-statusin-review). Do not read `docs/SRS.md`, `docs/DECISIONS.md`, `docs/decisions/` or the handbook end to end; search them for the ID or term you need.
